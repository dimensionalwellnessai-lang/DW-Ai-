# DW Wellness AI — Full App Audit

_April 20, 2026_

This is an honest inventory of where the app is right now: what works,
what's bloated, what's broken, what's missing, and concrete suggestions
for fixes. Findings are roughly ordered by visible user impact.

---

## 1. The Home / Command Center is doing too much (your complaint, expanded)

**File:** `client/src/features/home/home-command-center.tsx`
**File:** `client/src/components/life-system/three-ring-orbit.tsx`

### What's there now (top to bottom on one screen)

1. Hamburger button (top-left)
2. Greeting + first name + tiny pencil to edit name
3. Affirmation line (italic)
4. **Feeling chip row**: Calm / Off / Stressed / I feel triggered (4 chips)
5. **Three-ring orbit** with up to 9 inner pillars + up to 5 expression
   pillars + N project nodes + a center DW orb — each with a label
6. Carousel of cards: DW Reading → Insight Snapshot → Triggers this
   week → proactive cards (variable count) → DW Smart Import
7. Bottom nav (5 items)

That's roughly 20+ tap targets stacked vertically on a phone. The orbit
itself has up to ~14 labeled circles within a 340px square.

### Why it feels cluttered

- **Labels under every node**: `text` elements at `fontSize = size * 0.028`
  (≈10px) under each of 9–14 dots. At 340px wide that's a wall of tiny
  text overlapping at the diagonals.
- **Three competing "primary actions"**: the orbit center, the feeling
  chips, and the carousel all want attention at once. No clear hierarchy.
- **The chip row is visually inert for 3 of 4 chips** (Calm/Off/Stressed
  do nothing — only Triggered fires). Users tap and nothing happens.
- **Atmospheric glows** (two `blur-3xl/2xl` divs at 80% and 40%) sit
  *behind* the orbit but visually compete with the dotted ring guides.
- The **affirmation copy** changes every 15 minutes via
  `Math.floor(Date.now() / 3600000) + minuteSlot`. It feels random.
- The DW Smart Import card lives at the end of the carousel; nobody
  scrolls there.

### Concrete suggestions

**A. Hide labels by default; reveal on tap or hover.**
In `three-ring-orbit.tsx` the `<text>` element is rendered for every
node. Render labels only for the focused/hovered/lit node OR put them
on long-press. This single change cuts visual noise by ~70%.

**B. Make the orbit bigger and the chrome smaller.**
The orbit is the brand. Right now `max-w-[360px]` and `max-h-52vh`
shrink it to compete with the chip row above it. Drop the chip row
into the carousel as its own card ("How are you feeling?") and let the
orbit breathe at `min(420px, 60vh)`.

**C. Kill the dead chips or wire them up.**
Calm / Off / Stressed do nothing. Either:
- Remove them now and ship just the "I feel triggered" affordance, or
- Wire them to a lightweight mood pulse log (already proposed as
  follow-up task #66).

**D. Promote DW Smart Import out of the carousel.**
It's the single most strategic onboarding action and it's last in a
horizontal swipe. Put it right under the orbit as a single full-width
card *only when* the user's life-system is empty. Hide once populated.

**E. One source of greeting + status, not three.**
"Good evening, X" + affirmation + chip row is three lines doing the
same job (acknowledging the user). Collapse to:
> "Good evening, Daryl. **How are you feeling tonight?**"
…with the chips inline under it. Drop the italic affirmation entirely
or move it to the empty-state of the carousel.

**F. Reduce the orbit's outer-ring noise when there are many projects.**
`outerNodes` lays out projects at `(360 / max(projects.length, 3)) * i + 30`.
With 6+ active projects the labels collide. Cap visible project nodes
to 4–5 and show a "+N more" node that opens a project picker.

## 2. Navigation has three competing surfaces and inconsistent labels

**Files:** `client/src/components/bottom-nav.tsx` (113 lines),
`client/src/components/hamburger-menu.tsx` (349 lines),
`client/src/components/all-features-view.tsx` (365 lines),
`client/src/App.tsx` (542 lines, **100+ routes**)

### Findings

- The bottom nav calls the chat **"DW"**, the hamburger calls it
  **"Talk with DW"**, the floating orb calls it **"Talk with DW"**, and
  internally there are *two* chat pages: `/chat` (`AIWorkspace`) and
  `/talk` (`TalkItOutPage`). Users can't predict which one they're in.
- **All-Features View** + **Hamburger Menu** + **Bottom Nav** are three
  different ways to reach the same set of pages. There's no clear "this
  is for X, that is for Y" rule.
- `client/src/App.tsx` declares **100+ routes**. Many are gated by
  `isRouteEnabled` feature flags but they all still ship in the bundle.

### Duplicate / orphaned routes

| Route | Status |
|---|---|
| `/today` → redirect to `/command-center` | dead alias |
| `/home` → redirect to `/command-center` | dead alias |
| `/welcome` → redirect to `/enhanced-onboarding` | dead alias |
| `/voice-onboarding` → redirect to `/enhanced-onboarding` | dead alias |
| `/body` → redirect to `/habits` | dead alias |
| `/astrology` → redirect to `/cosmic-insights` | dead alias |
| `/life-blueprint` and `/life-blueprint-v2` | both point to same component |
| `/support/report` | declared **twice** (lines 307 & 329) |
| `/chat` and `/talk` | two different chat pages, same job |

### Suggestions

- **Pick one chat surface.** Either `/chat` (workspace) or `/talk`. Make
  the other a redirect. Update bottom nav, hamburger, and orb to all
  use the same label.
- **Delete the dead aliases** that aren't linked from anywhere.
- **Decide hamburger vs all-features.** They're 80% the same. Keep one.
- **Audit `isRouteEnabled` flags.** If a flag has been off for 30 days,
  delete the route and its page file.

## 3. Backend has a 14k-line monolith with active dead code

**File:** `server/routes.ts` — **13,964 lines**

This file handles OAuth, sessions, AI chat, billing, ingredient
categorization, scheduling, and ~everything in between. Side-effects:

- Hard to find anything. Search-and-edit is the only workflow.
- Easy to land changes in the wrong place. Example caught yesterday:
  trigger-protocol chat hook landed in `server/routes/chat.ts` —
  which is **never imported anywhere**. 100% dead code that
  duplicates the live `/api/chat` and `/api/chat/smart` routes in
  `server/routes.ts`.
- The pattern of having a `server/routes/` directory at all suggests an
  abandoned modularization attempt.

### Specific dead/duplicate files

- `server/routes/chat.ts` — `registerChatRoutes` exported but never
  called. Also redefines `detectTriggerSuggestion` (now properly lives
  in `server/routes/trigger-detection.ts`). **Delete it.** (Already
  proposed as follow-up #67.)
- `server/replit_integrations/chat/routes.ts` exports a
  `registerChatRoutes` of the same name. Easy to import the wrong one.

### Suggestions

- Delete `server/routes/chat.ts` outright (follow-up #67).
- Pick a slow modularization plan: one feature area per week extracted
  from `server/routes.ts` into `server/routes/<area>.ts`, mounted from
  a thin `server/routes.ts`. Don't try to do it all at once.

## 4. Security: dev-user fallback in chat

**File:** `server/routes.ts` lines 2110–2120 and 2389–2399

Both `/api/chat` and `/api/chat/smart` do this when there's no session:

```ts
let devUser = await storage.getUserByEmail("dev@wellness.local");
if (!devUser) {
  devUser = await storage.createUser({
    email: "dev@wellness.local",
    password: "devpassword123",
  });
}
userId = devUser.id;
req.session.userId = userId;
```

Effects:

- Anyone hitting the chat without a session gets logged in as a shared
  account with a hardcoded password. All their chat history, mood logs,
  goals, etc. land on the same user record across all anonymous users.
- The hardcoded password is checked into source control.
- This was probably useful during early dev. It is not safe in
  production.

### Suggestions

- Wrap the fallback in `if (process.env.NODE_ENV !== "production")` at
  minimum.
- Better: require auth on these endpoints and return 401 to anonymous
  callers, the same way every other route does.
- Rotate / delete the `dev@wellness.local` user from production DB if
  it exists there.

## 5. Billing is granting everyone "plus" tier

**File:** `server/routes.ts` lines ~1051–1075

Comment in code reads "billing stub — paywall disabled". Every
authenticated user is currently treated as a `plus` subscriber.

Effects:

- Subscription / paywall pages exist (`/subscription`, `/checkout`,
  `/paywall`) but cannot actually gate anything yet.
- Stripe integration is present in deps but not enforced server-side.

### Suggestions

- Decide whether this is intentional for the launch window.
- If it is: leave the stub but add a banner in `/subscription` so
  testers don't think the flow is wired.
- If it isn't: enable real entitlement checks and lock premium features.

## 7. Schema-vs-API drift: 100+ tables, many with no endpoints

**File:** `shared/schema.ts`

Tables defined but with no corresponding API routes that I could find:

- `vapid_keys` (used internally by push, fine)
- `scheduler_leases`, `monitoring_alerts` (internal infra, fine)
- `household_cleaning_tasks` — no CRUD endpoint
- `household_laundry_schedule` — no CRUD endpoint
- And several more "household" / "lifestyle" tables

This is database bloat from earlier feature explorations. They take up
schema mental load and migration time without paying back.

### Suggestions

- Audit each unused table. If the feature is dead, drop the table in
  the next migration. If it's "soon", note it in `replit.md`.
- The new `0012_trigger_events.sql` was the right pattern — every new
  table should ship with its versioned migration.

## 8. TypeScript health

`npx tsc --noEmit` is not clean. Sample of what's there:

- `Property 'updatedAt' does not exist on type 'GuestConversation'`
  in `client/src/pages/ai-workspace.tsx` line ~1893.
- Strict-null violations in `accountability-check-in.tsx` and
  `browse.tsx`.
- Literal-type comparison failures in `ai-workspace.tsx` line ~2316.
- SpeechRecognition API typing gaps in
  `enhanced-voice-mode-button.tsx` (lines 48–107).
- `Set<string>` and `MapIterator` need `--downlevelIteration` in
  `onboarding-wizard.tsx` and `reminder-scheduler.ts`.

### Suggestions

- Add a CI step that fails the build on new TS errors. Existing ones
  can be allow-listed via `// @ts-expect-error <reason>` so progress
  doesn't regress.

## 9. What's actually solid

To balance the picture — these are the parts that are working well:

- The **Life System** model (Core / Expression / Creation) is coherent
  and the new `emotional_regulation` pillar drops in cleanly because
  the per-pillar pattern is well-factored.
- The **Trigger Protocol v1** that just shipped is clean: aggregator,
  storage, sheet, home-tile, chat-hook, migration — all in their right
  places.
- **DW Smart Import** is a genuinely strong pitch. It deserves better
  placement (see §1.D).
- **Project workspaces** with inline editing (Tasks #61, #63, #64) are
  the most polished interaction in the app right now.

## 10. Recommended top 5 fixes (in priority order)

1. **De-clutter the home orb.** Hide node labels by default, kill the
   inert chips OR wire them, demote the affirmation, promote Smart
   Import. (§1)
2. **Lock the dev-user backdoor on chat.** It's a real production
   risk. (§4)
3. **Delete the duplicate chat module** (`server/routes/chat.ts`) and
   commit to one chat URL (`/chat` OR `/talk`). (§2, §3)
4. **Trim the route table** — kill dead aliases, retire feature-flagged
   routes that have been off for 30+ days. (§2)
5. **Decide on billing now** — either ship the paywall or hide the
   subscription pages. The half-state is confusing. (§5)
